# 架构与数据模型

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| API | FastAPI + uvicorn + Pydantic | JSON + SSE |
| 编排 | LangChain LCEL | 意图、RAG、流式；主路径 |
| 多智能体 | CrewAI（可选） | 意图官 → 执行员；失败降级 |
| 模型 | OpenAI 兼容 | DashScope / DeepSeek / Ollama |
| 向量库 | **Milvus** | 唯一 ANN 后端，不用内存向量库 |
| 会话与分块 | **PostgreSQL 16** | 会话、消息、文档、chunk 元数据 |
| ORM | SQLAlchemy 2 asyncio + asyncpg | Alembic 迁移 |
| 词面检索 | jieba + rank_bm25 | 进程内索引，语料来自 PG |
| 重排 | sentence-transformers bge-reranker-base | 可选 |
| 重试 | tenacity | LLM / Embedding / Milvus 短暂失败 |

不用：CoAgents、CopilotKit、LangGraph。前端第一期只用自包含 `dashboard.html`。

## 请求链路

```
客户端
  → 限流 / API Key
  → 语义缓存（仅首轮、非订单）
  → ChatPipeline
       ├─ Crew 可用 → 意图官 → 执行员（工具：RAG / 订单 / 售后）
       └─ 否则      → classify_intent → RAG | query_order | 闲聊
  → PostgreSQL 写入本轮消息
  → traces
```

JSON 与 SSE **必须**调用同一 Pipeline；SSE 只负责把 pipeline 的 stage/token 编码成 `text/event-stream`。

## PostgreSQL

### sessions

| 列 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 内部主键 |
| session_key | VARCHAR(128) UNIQUE NOT NULL | 客户端传入的 `session_id` |
| created_at | TIMESTAMPTZ | |
| updated_at | TIMESTAMPTZ | 每轮对话更新 |

### messages

| 列 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | |
| session_id | UUID FK → sessions.id | |
| role | VARCHAR(16) | `user` / `assistant` |
| content | TEXT | |
| intent | VARCHAR(32) 可空 | knowledge / order / chat / crew |
| sources | JSONB 默认 `[]` | `["file.md#3"]` |
| engine | VARCHAR(32) 可空 | langchain / crew |
| cache_hit | BOOLEAN 默认 false | |
| created_at | TIMESTAMPTZ | 排序用 |

索引：`(session_id, created_at)`。

读取：按 `created_at` 取最近 `retrieve_turns * 2` 条。写入后若超过 `max_turns * 2` 条，删除最旧的 user/assistant 对。

`memory.py` 只做仓储适配（`get_messages` / `add`），不要再持有进程内 dict 作为真相源。

### documents

| 列 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | |
| file_name | VARCHAR(512) | **原始文件名** |
| content_sha256 | CHAR(64) | 相同内容跳过或覆盖策略可配置 |
| chunk_count | INT | |
| created_at | TIMESTAMPTZ | |

### chunks

| 列 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 同时作为 Milvus `chunk_id` |
| document_id | UUID FK | |
| chunk_index | INT | 用于 `file.md#3` |
| title | VARCHAR(512) | 同 file_name，便于拼 source |
| content | TEXT | BM25 与重排用原文 |
| created_at | TIMESTAMPTZ | |

唯一约束：`(document_id, chunk_index)`。

## Milvus

- 服务：Standalone（compose 内嵌 etcd + local storage 即可，对标参考 `docker-compose-milvus.yml`）
- Collection 名：环境变量 `AIROBOT_MILVUS_COLLECTION`（默认 `aicustomer_kb`）
- 度量：`COSINE` 或 `IP`（与 embedding 归一化方式一致，写进配置注释）
- 启动：**创建不存在的 Collection，禁止默认 drop**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INT64 主键 auto_id 或 UUID 映射 | 内部行 id |
| chunk_id | VARCHAR | 对应 PG `chunks.id` |
| doc_id | VARCHAR | `{file_name}#{chunk_index}` |
| vector | FLOAT_VECTOR(dim) | dim 由所用 embedding 决定，启动对齐 |

检索：`search(vector, top_k)` 得到 `chunk_id` 列表 → 回表 PG 取 `content`（避免只靠 Milvus payload 漂移）。

`dim` 建议配置化或首次 embed 探测后建表；模型更换必须重建 Collection + 全量再入库。

## BM25

- 语料 = `SELECT content FROM chunks ORDER BY created_at, chunk_index`
- `add_documents` 必须 **extend 后重建 BM25Okapi**，禁止 `self._corpus = texts` 覆盖
- 进程重启：lifespan 里从 PG 全量重建
- 多副本：每实例各自重建（第一期可接受）；以后再考虑统一稀疏检索

## 环境变量（相对参考项目的增改）

必增：

```ini
# PostgreSQL
AIROBOT_DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/aicustomer

# Milvus（默认启用，不再提供 inmemory 作为生产路径）
AIROBOT_MILVUS_URI=http://localhost:19530
AIROBOT_MILVUS_COLLECTION=aicustomer_kb
AIROBOT_MILVUS_TOKEN=

# 鉴权
AIROBOT_API_KEY=
AIROBOT_AUTH_ENABLED=true
```

删除或不要照抄：`AIROBOT_VECTOR_STORE=inmemory`、`AIROBOT_MILVUS_RESET_ON_START=true`（持久化场景默认 false）。

## 从参考项目必须改掉的点

1. 会话不用内存 dict，用 PostgreSQL。  
2. 向量不用 InMemoryVectorStore，用 Milvus，重启不清空。  
3. BM25 追加 + 从 PG 重建。  
4. ingest 用原文件名。  
5. 同步与流式共用 Pipeline。  
6. 语义缓存读取 Settings。  
7. ingest/chat 加 API Key。  
8. 意图分类带历史。  
9. CI 把 tracing 单测也跑上。
