# 计划总表

按一个人全职、可并行部分任务估算。周期可按实际节奏压缩或拉长，**阶段顺序不要打乱**：先基础设施，再 RAG，再编排，最后评测交付。

新人请同时打开 [学习路线.md](./学习路线.md)：每个阶段都是 **先掌握知识并过关 → 再做任务清单**。下表「本阶段要掌握」只是摘要，细则、过关自测、先不要学什么都在学习路线里。

## 总览

| 阶段 | 名称 | 建议周期 | 本阶段要掌握 | 核心产出 | 完成定义 |
|---|---|---|---|---|---|
| 开工前 | 公共底子 | 1～3 天 | Python/venv、HTTP、Docker 基础、LLM 常识 | 本机环境 | 能起容器、能调通一个模型或 Ollama |
| P0 | 工程脚手架 | 2～3 天 | FastAPI、lifespan、env 配置、Compose 服务名 | 空服务 + health | `/health` 能连上 Milvus 与 PostgreSQL |
| P1 | 存储底座 | 3～4 天 | PG 表/外键/JSONB、SQLAlchemy、Alembic；Embedding、dim、Milvus Collection | 会话与向量可持久化 | 能写入一条会话、能写入一条向量并检索 |
| P2 | RAG 知识库 | 4～5 天 | RAG、分块、向量 vs BM25、RRF、重排、防幻觉 Prompt | 入库 + 混合检索 + 生成 | 上传 MD 后提问能命中并带来源 |
| P3 | 对话主链路 | 4～5 天 | 意图路由、多轮记忆、SSE、统一 Pipeline、Tool | 同步 + 流式对话 | 同一 `session_id` 重启后仍能追问 |
| P4 | 多智能体 | 2～3 天 | Agent/Task/Crew、sequential、降级、to_thread | 双 Agent + 降级 | 未装 crewai 时服务仍可用 |
| P5 | 稳定性与控制台 | 3～4 天 | 重试分类、限流、语义缓存、P95、API Key | 可观测 + 鉴权 | 控制台能看阶段耗时；ingest 需 API Key |
| P6 | 评测与交付 | 3～4 天 | RAGAS 四指标、Judge、CI、镜像分层 | 评测 + 一键部署 | CI 过语法+单测；compose 能拉起全栈 |

合计约 **3.5～4.5 周**。P2 与 P1 后半可部分重叠；P4 可在 P3 验收后再做，避免两套对话逻辑先分叉。

## 阶段计划

### P0 工程脚手架

**先学：** [学习路线 · P0](./学习路线.md#p0-工程脚手架建议-2～3-天)（FastAPI、lifespan、Compose、health）

| 项 | 说明 |
|---|---|
| 要掌握 | FastAPI 最小应用；启动钩子；环境变量配置；容器用服务名互连；健康检查探的是依赖不是只探进程 |
| 要做 | 建 `AICustomeRobort` 目录结构、`requirements`、`.env.example`、`docker-compose.yml`（app + postgres + milvus）、FastAPI 空应用、统一 Settings |
| 依赖 | Docker Desktop；Python 3.11 |
| 交付物 | 可 `docker compose up` 起 PG + Milvus；本地 `uvicorn` 返回 health |
| 验收 | `/health` 返回 `postgres: ok`、`milvus: ok`、当前 LLM/Embedding 模型名 |
| 不做 | 先不要写业务对话逻辑 |

### P1 存储底座

**先学：** [学习路线 · P1](./学习路线.md#p1-存储底座建议-3～4-天)（PostgreSQL + Embedding + Milvus）

| 项 | 说明 |
|---|---|
| 要掌握 | 四张表的职责；异步 ORM 与迁移；向量、维度、ANN、Collection；「原文在 PG、向量在 Milvus、id 对齐」 |
| 要做 | PostgreSQL：`sessions` / `messages` / `documents` / `chunks`；Alembic；异步仓储接口。Milvus：建 Collection、upsert、similarity search。启动时 **不** 清空 Collection（与参考项目 `RESET_ON_START=true` 相反，本项目要持久化） |
| 交付物 | `app/db/`、`app/rag/vectorstore.py`、迁移脚本 |
| 验收 | 单测或脚本：插入 2 轮对话能按 `session_id` 读回；插入 1 个 chunk 向量能 ANN 命中 |
| 风险 | Embedding 维度必须与 Collection `dim` 一致（DashScope v4 / nomic 维度不同，启动时校验） |

### P2 RAG 知识库

**先学：** [学习路线 · P2](./学习路线.md#p2-rag-知识库建议-4～5-天)（RAG、分块、混合检索）

| 项 | 说明 |
|---|---|
| 要掌握 | RAG 闭环；分块与 overlap；向量 vs BM25；RRF；重排可降级；Prompt 约束防幻觉；source 用原文件名 |
| 要做 | 文档解析（PDF/DOCX/MD/TXT）；分块；写入 PG chunks + Milvus；jieba+BM25（从 PG 加载语料，**追加而非覆盖**）；RRF；可选 reranker；RAG 生成 Prompt；`POST /api/v1/ingest` 使用**原始文件名**作 title |
| 交付物 | `app/rag/*`、示例 `data/knowledge_base.md`、ingest 接口 |
| 验收 | 问「退货运费谁承担」能答到规则，`sources` 为 `knowledge_base.md#N` |
| 避坑 | 参考项目 BM25 `add_documents` 会覆盖语料、ingest 用临时文件名当 title，本项目必须避免 |

### P3 对话主链路

**先学：** [学习路线 · P3](./学习路线.md#p3-对话主链路建议-4～5-天)（意图、记忆、SSE、Pipeline）

| 项 | 说明 |
|---|---|
| 要掌握 | 意图当路由器；分类要带历史；会话读写 PG；SSE 事件协议；JSON 与 SSE 共用一套 Pipeline |
| 要做 | **同一套** `chat_pipeline` 同时服务 JSON 与 SSE；意图 `knowledge/order/chat`；订单 Mock 工具；从 PG 取最近 N 轮；写回 user/assistant；意图分类带历史 |
| 交付物 | `app/services/chat.py`、`POST /api/v1/chat`、`POST /api/v1/chat/stream` |
| 验收 | 先问退货规则，再问「那运费谁出」仍走 knowledge；重启进程后同一 `session_id` 仍有上下文 |
| 硬性约束 | 禁止把 SSE 再写成一套独立 if/else（参考项目 JSON 走 Crew、SSE 不走） |

### P4 多智能体

**先学：** [学习路线 · P4](./学习路线.md#p4-多智能体建议-2～3-天)（Agent / Crew / 降级）

| 项 | 说明 |
|---|---|
| 要掌握 | Agent≠新语言；sequential 两段链；Tool 是函数；失败必须降级；同步 kickoff 要丢进线程池 |
| 要做 | CrewAI：意图识别官（无工具）→ 客服执行员（3 工具）；失败/未安装降级 P3 路由；Crew 路径也要回写 PG，并尽量带回 sources |
| 交付物 | `app/agents/crew.py`、`tools.py` |
| 验收 | `AIROBOT_USE_CREW=true` 且已装 extra 依赖时 `engine=crew`；关掉或卸掉后 `engine=langchain` 且功能等价 |

### P5 稳定性与控制台

**先学：** [学习路线 · P5](./学习路线.md#p5-稳定性可观测鉴权建议-3～4-天)

| 项 | 说明 |
|---|---|
| 要掌握 | 哪些错误可重试；滑动窗口限流；语义缓存双门限且读配置；P95；服务间 API Key |
| 要做 | tenacity 重试；按 IP 限流；语义缓存（配置必须读 Settings）；环形 traces；`/dashboard`；ingest/chat 的 `X-API-Key` |
| 交付物 | `app/services/resilience.py` 等、`static/dashboard.html` |
| 验收 | 超限 429；缓存 env 阈值生效；无 Key 时 ingest 401；dashboard 能流式提问并显示阶段耗时 |

### P6 评测与交付

**先学：** [学习路线 · P6](./学习路线.md#p6-评测与交付建议-3～4-天)

| 项 | 说明 |
|---|---|
| 要掌握 | 评测集怎么设计；RAGAS 四指标各抓什么；CI 无 Key 也要绿；镜像只打核心依赖 |
| 要做 | 评测集（可从参考项目 `qa.jsonl` 改编）；RAGAS 冒烟；CI（compile + 离线单测 + 可选 eval）；Dockerfile；README 快速开始 |
| 交付物 | `eval/`、`.github/workflows/ci.yml`、完整 README |
| 验收 | `python tests/test_stability.py` 与会话/仓储单测通过；`docker compose up --build` 可对话 |

## 依赖关系

```
P0 脚手架
  └─ P1 存储（PG + Milvus）
        └─ P2 RAG
              └─ P3 对话主链路（同步 + SSE 共用）
                    ├─ P4 CrewAI（可选层）
                    └─ P5 稳定性 / 控制台 / 鉴权
                          └─ P6 评测 / CI / Docker
```

## 明确不做（第一期）

- 不用 CoAgents / CopilotKit / LangGraph
- 不把 BM25 先上 Elasticsearch（启动从 PG 重建即可）
- 不把语义缓存/限流先上 Redis（第一期进程内；多副本时再拆）
- 订单系统第一期 Mock，预留 `ORDER_API_URL`
- 不做用户体系（登录注册）；鉴权只用服务间 API Key
