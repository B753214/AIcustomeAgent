## 0. 你要先建立的概念

```text
短时记忆 Short-term   = 当前会话最近对话原文（给模型看「聊过什么」）
摘要记忆 Summary      = 更早轮次的结构化压缩
情景记忆 Episodic     = 任务结论名片（告警 config/页码/证据摘要）——跨轮追问
工作记忆 / Checkpoint = 当前 Run 中间态（Alarm 用 harness_checkpoints）
长时记忆 Semantic     = 跨会话稳定事实（偏好等）——M4/M5
语义缓存 Cache        = 性能优化，必须按用户隔离，不是用户记忆
```

### 0.1 能力现状（2026-09-25 对齐，改计划依据）

| 层 | 现状 | 动作 | 落点 |
|----|------|------|------|
| **Short-term** | **已有** `chat_sessions` / `chat_messages` | **完善** | 去 default、user 隔离、Token 预算、消息元数据 |
| **Summary** | **无** | **新建** | `session_summaries` |
| **Episodic** | **无**结构化 | **轻量新建** | 优先 `chat_sessions.last_alarm_episode` JSON，**不**另建记忆中台 |
| **Execution** | **已有** `harness_checkpoints` | **不动**（规范边界即可） | 同 Run resume；禁存聊天/追问 |
| **Cache** | **已有** `SemanticCache` | **治理** | user/session scope、TTL/版本 |
| **Semantic** | **无** | **后期新建** | `memory_facts` + 召回（M4→M5） |
| **Run 台账** | **已有** harness_runs/events | **关联** | 消息挂 `run_id`，禁止平行 `agent_runs` |

**Episodic 说明：** 不是第二套聊天；会话上多挂结构化字段即可解决告警追问。消息表加字段解决「可追溯」，任务名片挂在 **session**。

**三类状态禁止混表：**

| 类型 | 存哪 | 生命周期 |
|------|------|----------|
| 会话对话 / 摘要 / episode | `chat_*` / `session_summaries` / `last_alarm_episode` | 跨轮、跟 session |
| Run 台账 / 事件 | `harness_runs` / `harness_run_events` | 跟 `run_id` |
| 步骤恢复 | `harness_checkpoints` | 同一次 Run resume |

原则（与完善计划一致）：

- PG 是真相源；向量只检索候选。  
- 显式事实优先于模型推断。  
- **不新建**平行 `agent_runs`；消息挂 `run_id` → `harness_runs`。  
- **不改** `AgentRuntime` 核心来塞记忆；装配挂在 `services/chat` 等入口。  
- **不改** `harness_checkpoints` schema 存聊天/追问。  
- 写入对齐 H6 `DataPolicy`。

### M1：会话安全与生命周期

#### Memory-M1-1 — 取消 default / 服务端发号

1. **人话**  
   没有全站共享的 `default` 会话；空则服务端发 UUID。

2. **痛点**  
   `ChatRequest.session_id = "default"`；`ChatExecutor` 有 `or "default"`。

3. **做完后**  
   不传 session → 响应带回新 id；再用该 id 有上下文；代码无聊天 default 字面量。

4. **建议文件**  
   - `app/schemas.py`  
   - `app/services/chat.py`（`run` / `run_astream`）  
   - `app/agents/harness_chat/executor.py`  
   - `app/harness/adapter/chat_http.py`  
   - `app/main.py`

5. **要点**  
   - `session_id: Optional[str] = None`  
   - 空 → `uuid4()`；`meta["session_id"]` 回传  
   - Harness / 旧路径行为一致

6. **验收**  
   手测 3 步 + 全库聊天路径无 `"default"` 会话写入。

7. **不要做**  
   本步可不落库 `user_id`（紧接着 M1-2）；但 Header 解析建议一起做。

---

#### Memory-M1-2 — 读写绑定 user_id

1. **人话**  
   会话表有主人；读写必须 `user_id + session_id`。

2. **痛点**  
   无 `user_id`；history/list 可越权。

3. **做完后**  
   A 的历史 B 读不到；列表只见自己的会话。

   - `app/models/sessions.py`：加 `user_id`、`updated_at`、`status`（`tenant_id` 可空预留）  
   - `app/services/session_service.py`  
   - `app/services/auth.py`：`get_user_id`（`X-User-Id`）  
   - history / sessions API

5. **要点**  
   - 第一版可保留 `session_id` 作 PK，查询强制带 `user_id`  
   - 旧数据迁移默认 `anonymous`  
   - 完整拆 `id` + `session_key` 可后置，但蓝图目标保留

6. **验收**  
   换 `X-User-Id` 同 session_id → 404 或空。

7. **不要做**  
   不做长期事实表。
