# Agent 记忆系统完善计划

> **跟做请用：[记忆系统跟做计划.md](./记忆系统跟做计划.md)**（`开始 Memory-M0-1` …）。  
> 本文是完整版蓝图与指标；施工步骤以跟做计划为准。  
> 精简第一版备选：[记忆系统优化.md](./记忆系统优化.md)。  
> **2026-09-25 修订：** 对齐已落地的 Harness（H5 Run/Event/Checkpoint、H6 Policy/脱敏）。会话记忆与 Run 台账、步骤 Checkpoint 分层，避免重复建设。

## 1. 建设目标

在保留现有 PostgreSQL 会话历史的基础上，将当前“最近轮次对话记忆”逐步扩展为具备用户隔离、上下文压缩、长期事实、相关性召回、任务状态恢复和效果评测的完整 Agent 记忆系统。

目标记忆分层：

```text
Agent Memory
├── Short-term Memory    最近原始消息，按 Token 预算装配   【已有 → 完善】
├── Summary Memory       较早对话的滚动结构化摘要         【新建】
├── Semantic Memory      用户偏好、身份、长期约束和稳定事实 【新建 · 后期】
├── Episodic Memory      会话级任务名片（建议 session JSON）【轻量新建】
├── Execution State      harness_checkpoints               【已有 · 不动】
└── Semantic Cache       性能优化，与用户记忆严格隔离       【已有 → 治理】
```

**落地口径（2026-09-25）：** Episodic ≠ 独立记忆中台；优先 `chat_sessions.last_alarm_episode`。消息表扩字段解决追溯，不替代任务名片。

## 2. 建设原则

- PostgreSQL 是记忆事实的唯一真相源，向量库只负责检索候选。
- 用户显式表达优先于模型推断，模型不能直接决定永久事实。
- 短期上下文按 Token 预算管理，不再只按固定轮数截断。
- 长期记忆只保存稳定、可复用、可追溯的事实。
- **Checkpoint 是执行状态，不与用户画像或聊天摘要混表；** Alarm 步骤恢复用 `harness_checkpoints`，会话追问用情景快照，二者禁止混用。
- **Run 台账复用 `harness_runs` / `harness_run_events`，** 不平行再建 `agent_runs`（除非未来有充分理由拆离 Harness）。
- 知识库向量与用户记忆向量分开存储和授权。
- 所有记忆均可查看、修正、失效、删除和审计；写入对齐 H6 `DataPolicy` 脱敏。
- 记忆装配挂在 `services/chat`（及同类入口），**不改 AgentRuntime 核心**。
- 采用渐进迁移，现有 Chat/RAG/Alarm API 在改造期间保持兼容。

## 3. 总体计划表

| 阶段 | 名称 | 建议周期 | 核心工作 | 主要交付物 | 完成标准 |
|---|---|---:|---|---|---|
| M0 | 基线与记忆边界 | 1～2 天 | 明确记忆分类、采集范围、隐私规则和基线用例 | 记忆规范、基线报告、数据流图 | 团队能区分会话记忆、长期记忆、Checkpoint 和缓存 |
| M1 | 会话安全与生命周期 | 3～4 天 | 用户隔离、内外 ID、并发创建、归档和删除 | 新会话模型、Repository、迁移脚本、鉴权测试 | 不同用户不能读取或污染彼此会话 |
| M2 | 丰富消息与 Run 数据 | 3～5 天 | 消息挂 intent/engine/`run_id`；**复用** harness Run；审计字段 | 消息扩展、与 `harness_runs` 关联 | 任一回答可追溯到 Run/事件 |
| M3 | Token 窗口与摘要 | 4～6 天 | Token 预算、滚动摘要、上下文装配 | Context Builder、Summary Service、摘要表/字段 | 长对话不超上下文且关键事实不明显丢失 |
| M4 | 长期事实记忆 | 5～7 天 | 事实抽取、审核、去重、冲突、过期和删除 | `memory_facts`、Memory Policy、管理接口 | 稳定事实可跨会话使用，临时信息不会误写入 |
| M5 | 相关性召回 | 4～6 天 | 语义检索、用户过滤、时间衰减和重排 | Memory Retriever、向量索引、召回评测 | 只向 Prompt 注入当前问题真正相关的用户记忆 |
| M6 | Agent 情景与（可选）图恢复 | 4～7 天 | RAG 改写、Alarm **会话**情景；LangGraph Checkpointer **可选** | episode 存储、改写链路；（可选）图 Checkpointer | 告警追问可复用；图恢复不挡第一版 |
| M7 | 缓存治理与评测 | 4～6 天 | 缓存隔离、记忆指标、回归集、人工审核 | 评测集、指标报告、Dashboard 指标 | 错误记忆率和跨用户泄露为零，核心指标达到门槛 |

按一人全职估算，总周期约 5～7 周。M4 与 M5 应串行推进：先确保写入内容可信，再做语义召回。

## 4. 当前系统基线（2026-09-25，Harness 后）

| 能力 | 当前实现 | 主要缺口 |
|---|---|---|
| 会话持久化 | PostgreSQL `chat_sessions` / `chat_messages` | `session_id` 作主键，缺少 `user_id`；仍有共享 `default` 风险 |
| 历史读取 | 最近 `memory_max_turns * 2` 条 | 只按轮数，不按 Token；库内旧消息不裁剪 |
| Agent 注入 | Router/Chat/RAG/Crew 用历史；Harness Chat 仍调 `run_astream` | Alarm 追问弱；各路径未统一 ContextBuilder |
| 消息内容 | `role`、`content`、`created_at` | 未保存 intent、source、tool、`run_id` |
| Harness Run | `harness_runs` + `harness_run_events` 短事务落库 | 与聊天消息尚未关联；勿再造平行 Run 表 |
| Alarm 步骤恢复 | `harness_checkpoints` + 幂等键（H5） | **同 Run resume 已有**；缺的是**跨轮会话情景**追问 |
| LangGraph 状态 | 单次请求内 ephemeral，`g.compile()` 无 checkpointer | 跨请求图恢复仍缺（第一版可不做） |
| 语义缓存 | 进程内向量 + 词面；有 history/alarm 时跳过 | 跨用户共享风险、无 TTL/版本 scope |
| 脱敏 | H6 `DataPolicy` 在 Runtime emit 路径 | 会话 metadata / 摘要写入尚未统一走同一套 |
| 长期用户记忆 | 无 | 无偏好、事实、冲突、遗忘和删除机制 |

## 5. 分阶段实施计划

### M0：基线与记忆边界

| 编号 | 任务 | 交付物 | 验收方式 |
|---|---|---|---|
| M0-1 | 定义短期、摘要、长期事实、情景、Checkpoint、缓存的边界 | 记忆分类说明 | 每类数据有明确生命周期和存储位置 |
| M0-2 | 定义允许记忆、禁止记忆和需脱敏字段 | 数据策略表 | Token、密码、身份证明等不得进入 Trace 或长期记忆 |
| M0-3 | 收集当前多轮场景作为基线 | 评测 JSONL | 覆盖 Chat、RAG、Alarm 追问和跨用户隔离 |
| M0-4 | 记录当前命中率、正确率、Token、P95 | 基线报告 | 后续每阶段能与基线对比 |
| M0-5 | 明确数据保留和用户删除规则 | Retention Policy | 会话、Run、事实、Checkpoint 均有保留期限 |

### M1：会话安全与生命周期

#### 目标数据模型

`chat_sessions` 建议调整为：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID PK | 数据库内部主键 |
| `session_key` | VARCHAR(128) UNIQUE | 客户端使用的会话标识 |
| `tenant_id` | VARCHAR/UUID | 租户隔离，可为空但应预留 |
| `user_id` | VARCHAR/UUID | 会话所有者 |
| `title` | VARCHAR(256) | 会话标题 |
| `status` | VARCHAR(16) | active、ended、archived、deleted |
| `created_at` | TIMESTAMPTZ | 创建时间 |
| `updated_at` | TIMESTAMPTZ | 最后活动时间 |
| `ended_at` | TIMESTAMPTZ | 结束时间 |
| `expires_at` | TIMESTAMPTZ | 自动过期时间 |
| `version` | INT | 乐观锁或并发更新版本 |

| 编号 | 任务 | 验收标准 |
|---|---|---|
| M1-1 | 取消公共默认会话或由服务端安全生成 `session_key` | 未提供会话 ID 时不会落入共享的 `default` 会话 |
| M1-2 | 所有会话读写绑定 `tenant_id + user_id` | 用户 A 无法读取用户 B 的历史 |
| M1-3 | 使用唯一约束和 Upsert 处理并发首次请求 | 同一会话并发创建不报重复主键 |
| M1-4 | 增加创建、结束、归档、清空和删除操作 | 生命周期字段与实际行为一致 |
| M1-5 | 实现保留期清理任务 | 过期会话可归档或删除，操作可审计 |
| M1-6 | 校验 `session_key` 和消息长度 | 超长、空值和非法标识返回明确 4xx |

### M2：丰富消息与 Agent Run（复用 Harness）

`chat_messages` 建议增加：

| 字段 | 用途 |
|---|---|
| `intent` | 本轮路由意图 |
| `engine` | chat_react、rag、alarm、crew |
| `sources` JSONB | RAG、告警和工具来源摘要 |
| `tool_calls` JSONB | 工具名称及脱敏参数摘要（可瘦；明细在 events） |
| `model` | 实际使用模型（可选） |
| `run_id` | **关联 `harness_runs.id`**（Harness 路径必填） |
| `metadata` JSONB | 可扩展元数据（经 DataPolicy） |

**Run 台账：** 默认使用已有 `harness_runs` / `harness_run_events`（status、error、usage、事件流）。  
仅当未来有「非 Harness 执行也必须独立审计」且无法挂 harness 表时，再评估扩展表——**第一版不做新 `agent_runs`。**

| 编号 | 任务 | 验收标准 |
|---|---|---|
| M2-1 | 扩展消息模型并建立数据库迁移 | 旧消息可正常读取，新字段有默认值 |
| M2-2 | 消息写入绑定 Runtime `run_id` | Harness 路径下可联表查到 `harness_runs` |
| M2-3 | 保存 Router、Tool、Source 摘要（或引用 events） | 任意回答可追溯关键路径 |
| M2-4 | 字段级脱敏，对齐 H6 `DataPolicy` | API Key、密码、Cookie、手机号等不落库 |
| M2-5 | 历史 API 增加安全的详细/简略模式 | 普通用户看消息，管理员按权限看执行摘要 |

### M3：Token 窗口与滚动摘要

#### 上下文装配顺序

```text
System Prompt
+ 当前相关长期事实
+ 会话摘要
+ 最近原始消息
+ 当前问题
<= 模型上下文预算
```

建议增加 `session_summaries`：

| 字段 | 说明 |
|---|---|
| `session_id` | 所属会话 |
| `summary` JSONB | topic、known_facts、decisions、unresolved |
| `from_message_id` | 摘要起点 |
| `through_message_id` | 已覆盖到的最后消息 |
| `prompt_version` | 摘要 Prompt 版本 |
| `created_at` / `updated_at` | 版本时间 |

| 编号 | 任务 | 验收标准 |
|---|---|---|
| M3-1 | 实现模型 Token 估算器 | 上下文装配前能得到稳定的 Token 估算 |
| M3-2 | 用 Token Budget 替代固定轮数作为主限制 | 长消息不会因“轮数少”而撑爆上下文 |
| M3-3 | 定义结构化摘要 Schema | 摘要包含主题、事实、决策和未解决问题 |
| M3-4 | 超阈值后滚动总结较早消息 | 最近消息保留原文，旧消息只总结一次 |
| M3-5 | 摘要失败时安全降级 | 失败不影响正常对话，原始消息仍可恢复 |
| M3-6 | 给摘要记录覆盖范围和 Prompt 版本 | 可判断摘要是否过期或需要重建 |

### M4：长期事实记忆

新增 `memory_facts`：

| 字段 | 说明 |
|---|---|
| `id` | UUID PK |
| `tenant_id` / `user_id` | 严格隔离范围 |
| `kind` | profile、preference、constraint、business_fact |
| `normalized_key` | 去重和冲突键，如 `response_style` |
| `content` | 规范化事实文本 |
| `confidence` | 抽取置信度 |
| `importance` | 召回优先级 |
| `source_message_id` | 事实来源 |
| `source_type` | explicit、inferred、imported |
| `valid_from` / `valid_until` | 有效期 |
| `status` | candidate、active、superseded、deleted |
| `created_at` / `updated_at` | 审计时间 |

| 编号 | 任务 | 验收标准 |
|---|---|---|
| M4-1 | 定义可记忆和不可记忆分类 | 天气、临时订单状态、模型猜测不会写入长期事实 |
| M4-2 | 使用结构化输出抽取候选事实 | 每条候选包含类型、键、置信度和来源 |
| M4-3 | 实现规则过滤、去重和归一化 | 重复表达不会生成大量等价事实 |
| M4-4 | 实现冲突与替代逻辑 | 新偏好激活后，旧偏好标记 `superseded` |
| M4-5 | 明确自动写入与待确认阈值 | 低置信度和敏感事实需要用户确认 |
| M4-6 | 提供查看、修正、遗忘和删除能力 | 用户可以控制自己的全部长期记忆 |
| M4-7 | 建立记忆审计日志 | 能追溯谁在何时因哪条消息修改了事实 |

### M5：相关性召回

个人长期记忆建议以 PostgreSQL 为事实源。数据量不大且需要强过滤、事务和删除时，优先使用 PostgreSQL + pgvector；如不引入 pgvector，则使用独立 Milvus Collection，不能与知识库 Collection 混用。

召回分数建议包含：

```text
final_score = semantic_similarity
            + importance_weight
            + recent_use_weight
            - time_decay
```

| 编号 | 任务 | 验收标准 |
|---|---|---|
| M5-1 | 为 active 事实生成向量并保存索引引用 | 原文、状态和向量可一致删除 |
| M5-2 | 查询强制携带 tenant/user 过滤 | 不可能召回其他用户记忆 |
| M5-3 | 实现相关度、重要度和时间衰减重排 | 当前无关偏好不会进入 Prompt |
| M5-4 | 设置召回阈值、数量和 Token 上限 | 注入内容不会挤占主要对话上下文 |
| M5-5 | 记录候选、最终注入项和使用原因 | 可评估“召回了什么、为什么使用” |
| M5-6 | 对已失效、删除、过期事实立即过滤 | 状态变更后下一请求不再召回 |

### M6：各 Agent 的情景记忆与执行恢复

| Agent | 记忆改造 | 验收场景 |
|---|---|---|
| Router | 使用摘要、最近消息 | “那继续查一下”能正确关联上一轮意图 |
| Chat | 注入相关偏好（第二版）和最近历史 | 多轮连贯；偏好跨会话属 M4 |
| Knowledge/RAG | 将历史追问改写为独立检索问题 | “那运费谁出”可结合上一轮主题正确检索 |
| CrewAI | 传结构化 Context，不再拼接全部历史文本 | 多 Agent 获得一致且受预算约束的上下文 |
| Alarm | **会话级** episode（实体、证据、页码）；步骤恢复已用 harness checkpoint | 后续追问无需再次提供完整告警原文 |

#### Alarm：两层状态（必须分清）

| 层 | 存储 | 用途 |
|---|---|---|
| 步骤恢复 | `harness_checkpoints`（已有） | 同一次 Run 中断后续跑；幂等键防重放 |
| 会话情景 | `last_alarm_episode` / 小表（Mem 要做） | 跨轮「看第 2 页」等追问 |

建议 episode 至少保存：`config_id`、监控 URL、指标、级别、证据摘要、页码、playbook 提示、可选 `source_run_id`。

| 编号 | 任务 | 验收标准 | 优先级 |
|---|---|---|---|
| M6-0 | 文档与代码边界：会话 episode ≠ harness checkpoint | 评审通过；无混表写入 | **第一版必做（规范）** |
| M6-A | Alarm 会话情景读写 + 追问合并 | 「看第 2 页」复用 config/url | **第一版（= Mem-Day8）** |
| M6-1 | 为 LangGraph 接入持久化 Checkpointer | 进程重启后可按 `thread_id` 恢复 | **第二版 / 可选** |
| M6-2 | （已完成于 H5）Alarm 步骤 Checkpoint Schema | — | **已完成，勿重复** |
| M6-3 | （已完成于 H5）外部写/浏览器幂等键 | — | **已完成，勿重复** |
| M6-4 | checkpoint 版本与代码版本（加固） | 不兼容状态拒绝恢复 | 可选加固 |
| M6-5 | 取消、失败、过期与人工终止 | 终止 Run 不继续调工具 | 与 Harness 取消语义对齐 |

### M7：语义缓存治理与记忆评测

缓存键至少包含：

```text
agent + model + prompt_version + kb_version
+ tenant/user_scope + normalized_query
```

| 编号 | 任务 | 验收标准 |
|---|---|---|
| M7-1 | 个性化、订单、天气和告警默认不进入共享缓存 | 不会把用户 A 的回答返回给用户 B |
| M7-2 | 增加 TTL、版本、容量和主动失效 | Prompt/知识库升级后旧缓存不再命中 |
| M7-3 | 多进程后按需要迁移 Redis | 各实例缓存策略一致，可集中失效 |
| M7-4 | 建立记忆写入和召回评测集 | 覆盖正确写入、不该写入、冲突、过期和删除 |
| M7-5 | 建立长对话与跨会话回归集 | 摘要和长期记忆不会改变关键事实 |
| M7-6 | Dashboard 展示记忆指标 | 可观察命中、错误、延迟、Token 和删除情况 |

## 6. 记忆运行流程

### 请求前

1. 根据认证身份校验 `tenant_id + user_id + session_key`。
2. 加载会话摘要和最近消息。
3. 使用当前问题检索相关长期事实。
4. 按 Token Budget 组装上下文。
5. 记录实际注入的记忆 ID 和原因。

### Agent 执行后

1. 保存 user/assistant 消息及 intent、source、tool、model 元数据（脱敏）。
2. 关联已有 `harness_runs`（写入/确认 `run_id`）；不另起平行 Run。
3. 超过阈值时异步生成滚动摘要。
4. （第二版）抽取长期事实候选并执行规则过滤。
5. （第二版）根据置信度自动激活或进入待确认状态。
6. 写入审计记录；（第二版）更新记忆向量。

## 7. 评测指标与门槛

| 维度 | 指标 | 初始建议门槛 |
|---|---|---:|
| 隔离 | 跨用户记忆泄露率 | 0 |
| 写入 | 应记忆事实准确率 | ≥ 95% |
| 拒绝写入 | 临时/敏感/推断事实拦截率 | ≥ 98% |
| 召回 | Memory Precision@K | ≥ 90% |
| 召回 | Memory Recall@K | ≥ 85% |
| 忠实度 | 注入记忆与来源一致率 | ≥ 98% |
| 摘要 | 关键事实保留率 | ≥ 95% |
| 冲突 | 新旧事实正确替代率 | ≥ 95% |
| 遗忘 | 删除后再次召回率 | 0 |
| 恢复 | 安全 Checkpoint 恢复成功率 | ≥ 95% |
| 性能 | Memory 装配 P95 | 初期 ≤ 300 ms |
| 成本 | 记忆额外 Token 占比 | 建议 ≤ 总上下文 25% |

硬失败包括：跨用户泄露、删除后仍召回、把模型猜测写成确定事实、泄露 Token/密码、恢复时重复执行有副作用的操作。

| 测试类型 | 必测内容 |

## 9. 主要风险与控制措施

| 风险 | 表现 | 控制措施 |
|---|---|---|
| 错误永久化 | 模型推断被当成用户事实 | 候选态、置信度、来源、用户确认 |
| 召回污染 | 无关事实挤占上下文或误导回答 | 用户过滤、阈值、重排、Token 上限 |
| 摘要失真 | 压缩后遗漏或改变关键事实 | 结构化摘要、来源范围、黄金回归集 |
| 隐私泄露 | 跨用户读取或敏感数据落库 | 强制身份过滤、字段脱敏、审计与删除 |
| 无限增长 | 消息、Run、Checkpoint 持续积累 | Retention、归档、TTL 和后台清理 |
| 恢复副作用 | 重复抓取、登录或外部写入 | 幂等键、步骤恢复策略、人工确认 |
| 缓存串话 | 共享缓存返回其他用户内容 | Scope/版本键、个性化结果不共享 |
| 迁移回归 | 新上下文改变现有 Agent 行为 | 特性开关、双轨对比、逐 Agent 上线 |

## 11. 第一版建议范围

为了尽快获得用户体验收益，第一版建议只交付（与 [记忆系统优化.md](./记忆系统优化.md) 一致）：

1. 会话与用户强隔离，取消共享 `default` 会话（含 Harness Adapter）。
2. 消息保存 intent、engine、sources 摘要和 **`run_id`→`harness_runs`**。
3. 上下文改为 Token Budget（`context_builder` 挂在 chat 服务层）。
4. 增加滚动结构化摘要。
5. RAG 增加历史问题改写。
6. Alarm **会话级** `last_alarm_episode`，支持基础追问（**不**重做 H5 checkpoint）。
7. 语义缓存按 user/session 隔离；写入对齐 DataPolicy。

长期事实向量召回、LangGraph 持久 Checkpointer 放到第二版。Alarm **同 Run** 恢复已在 Harness H5 完成。

## 12. 暂不纳入第一版

- 不自动记忆所有对话内容。
- 不把知识库和用户记忆放进同一个向量集合。
- 不允许模型无审核地写入敏感或永久事实。
- 不拆分独立 Memory 微服务。
- 不在低数据量阶段引入复杂图数据库。
- 不用长期记忆替代业务数据库中的订单、天气或监控事实。
- **不新建平行 `agent_runs` 表。**
- **不修改 `harness_checkpoints` 来存聊天历史或跨轮追问。**
- **不为 Mem 改 `AgentRuntime` 核心。**
